## Lowering match environment (design — option **B**)

**Stakeholder choice (2026-04-23):** Thread match-time context beyond the item arena (**`item_tags` / `item_names` / `item_d2` / …**) using **(B) a documented packed `Vec<i32>`** (plus existing program-level vecs where they already exist), **not** **(A)** an ever-growing tail of parallel parameters on **`lower_expr_to_value`** and every tag helper.

**Rationale:** new fields (**per-fn param name/type pairs**, scrut-local stacks, future import-alias slices) should land as **new regions** in one **versioned** buffer with a single pack/unpack story. That maximizes **flexibility** and keeps **comprehensive** SML parity work from re-touching dozens of signatures (and from fighting bootstrap **function-count** / per-function **expression-depth** limits) every time the match pipeline gains another table.

**Sketch: `lower_match_env: Vec<i32>` v0 (indices are element offsets into the same vec)**

1. **`[0]`** — **`magic`**: sentinel **`0x4D450001`** (**`1297235969`** as **`i32`**) if the vec is a real env, or **`0`** when callers pass an **empty** vec and callees synthesize fresh callee tables locally (today’s **`lower_tag_match`** behaviour).
2. **`[1]`** — **`version`**: **`1`** for this layout.
3. **`[2]`** — **`fn_names_base`**: start index of the **`fn_names`** flat run (**`-1`** if none inlined).
4. **`[3]`** — **`fn_ret_base`**: parallel **`fn_ret`** run (**`-1`** if none).
5. **`[4]`** — **`fn_count`**: length of those two parallel runs ( **`0`** when tables are built fresh per match).
6. **`[5]`** — **`param_names_base`**: stride-1 name-token handles (**`-1`** until **`lower_fn`** threads params).
7. **`[6]`** — **`param_ty_base`**: stride-1 typedef / token handles (**`-1`** until wired).
8. **`[7]`** — **`param_count`**: **`0`** until wired.
9. **`[8]`** — **`scrut_base`**: start index of **interleaved** scrut-local rows **`(name_h, ty_h)`** (**`-1`** when empty).
10. **`[9]`** — reserved (**`-1`** in interleaved v0). **`lower_match_env_merge_parent_scrut`** also accepts legacy parallel parents (**`[8]`** = names base, **`[9]`** = types base).
11. **`[10]`** — **`scrut_count`**: scrut-local pair count (**`0`** until wired).

**Packing rule:** regions are **contiguous** sub-slices of **`lower_match_env`**; bases are **absolute indices**; lengths live in the header. Helpers **`lower_match_env_alloc`**, **`lower_match_env_slice`**, **`lower_match_env_set_fn_table`** (names) keep call sites small.

**Migration order:** (1) introduce vec + helpers + **`magic=0`** “legacy empty” path — **landed:** **`lower_match_env_*`** + **`test_lower_match_env_helpers`**; (2) move **`lower_top_fn_tables_for_match`** output into a packed region for **`lower_tag_match`** — **landed:** **`lower_match_env_append_top_fn_match_tables`**; (3) thread ItemFn param name / type-head token runs into **`[5..7]`** — **landed:** **`lower_match_env_append_item_fn_param_rows`** + **`lower_scan_item_fn_param_names_ty_toks`** (lowering-local token walk, no **`checker.sv0`**); **`match_scrut_cty`** reads callee tables from **`[2..4]`** and param tables from **`[5..7]`** directly (**no unpack** for probe); (4) scrut-local **`[8..10]`** — **landed (2026-04-23):** interleaved pairs via **`lower_match_env_append_scrut_pair`** / **`lower_match_env_merge_parent_scrut`** / **`lower_match_env_clone`**; **`match_scrut_cty`** probes packed scrut before params; **`lower_tag_match`** merges inherited env, records scrutinee 1-seg path after **`bind_scrut_var`**, threads **`match_env_inherit`** through **`lower_expr_to_value`**; **`lower_match_arms`** clones env + **`PatBind`** row per arm. **2026-04-25:** **`PatEnum`** tuple binds and **`PatStruct`** field binds that lower to **`Assign`** now also call **`lower_match_env_append_scrut_pair`** (same **`scrut_cty`** token handle as **`PatBind`**) so nested **`match_scrut_cty`** on those names works inside the arm body. Remaining: per-field / per-payload **precise** typedef handles if **`scrut_cty`** (whole scrutinee) proves too coarse vs SML.

## M3 G3 — Parser item arena + program sidecars (normative for G4)

**Gates M3-S-022 … M3-S-026** (see milestone task) require the parser to retain enough **item-row** and **program-local** data for **`resolve_top_item`** / **`initTypes`**-class passes without re-parsing source text for information that was already consumed.

**Item rows (`it`, `id1`…`id5`) — summary**

| Tag | Meaning | `id1` | `id2` | `id3` | `id4` | `id5` |
|-----|---------|-------|-------|-------|-------|-------|
| 0 ItemFn | Top-level / trait-method / impl-method fn | name tok | packed: **has_ret** = `id2%2`, **contract_count** = `id2/2` | param_count | **body_root** (index in shared per-program `body_et` expr arena) | base into **`fn_param_name_toks`** (length = **param_count**; **`-1`** = **`_`**) |
| 1 ItemStruct | Struct def | name tok | field_count | **sf_base** | field_count (slice **`struct_field_name_toks[sf_base .. sf_base+count)**`) | `-1` |
| 2 ItemEnum | Enum def | name tok | variant_count | **ev_base** | variant_count (slice **`enum_variant_name_toks[ev_base .. ev_base+count)**`) | `-1` |
| 3 / 4 | Trait / Impl | per parser | per parser | 0 | `-1` sentinel for parent rows | `-1` |

**Program-local sidecar Vecs** (filled only by **`parse_program`** / **`parse_item`**): **`enum_variant_name_toks`** — token indices of each enum variant’s leading **IDENT**; **`struct_field_name_toks`** — token indices of each struct field’s name **IDENT**; **`fn_param_name_toks`** — each **`ItemFn`** parameter name token (same order as **`id3`**); **`struct_field_ty_root`** — parallel to **`struct_field_name_toks`**, each entry is an index into the **program** type arena (**`pty_tt`** / **`pty_td*`** shared with **`parse_type`** for struct fields and **`type`** aliases). Callers that own the item arena after **`parse_program`** must hold these Vecs alongside **`body_et`** / **`body_ed*`** / **`body_sf`** and the program type arena for **`resolve_ty`** on **`ItemStruct`** / **`ItemTypeAlias`** (**`ItemFn`** param/ret types still use **per-fn** local type arenas until merged).

**Helpers in `lib/parser.sv0`:** **`item_fn_has_ret_packed`**, **`item_fn_contract_count_packed`** unpack **`ItemFn.id2`**.

**G4 (in progress):** parser adds **`id5`** / **`fn_param_name_toks`**; **program** **`pty_tt`** holds struct-field and **`type`**-alias types (**`struct_field_ty_root`** parallels **`struct_field_name_toks`**; **`ItemTypeAlias.id2`** is the alias RHS root); **`resolve_program`** threads expr + type sidecars; **`resolve_top_item`** resolves **`ItemFn`** bodies, **`ItemStruct`**/**`ItemTypeAlias`** **`resolve_ty`**. **`ItemFn`** param/ret **`resolve_ty`** (still parsed into **per-fn** local type arenas), enum variant payload **`resolve_ty`**, and contract expr walks remain follow-on work.
